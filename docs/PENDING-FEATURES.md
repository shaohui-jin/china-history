## 风险

### R1 移动端「展开其余 N 条事件」曾失效 — ✅ 已修复

**曾有的问题**：`timelineLite` 已滤掉 `sig<4`，`TimelineVertical` 内部再滤一次，导致 `hiddenCount` 恒为 0，「展开其余 N 条」按钮永不渲染，sig=3 的次要事件在移动端完全看不到。

**修复**：两个页面的 `TimelineVertical` 改收全量 `timeline`（组件自身已有折叠逻辑，数据只多 3 条）。
改动点：[timeline.astro](src/pages/timeline.astro)、[index.astro](src/pages/index.astro)。

**实测验证**（Playwright 375px）：按钮文案「展开其余 1 条事件」，点击后条目 9 → 10。

留在文档里是因为：**以后若为了首屏体积想再改回 `timelineLite`，必须同时改 `TimelineVertical` 的折叠实现**，否则会重新踩同一个坑。

---

### R2 `buildEras` 不依赖调用方排序 — 已有测试保护

**背景**：分段是按数组顺序切的，如果传入未排序数据，`from`/`to` 会算错。函数内部已有 `sort`，但这是隐式契约。

**现状**：已补测试「乱序输入结果与排序后一致」「重复年份不拆分」「单条事件不崩」，`npm test` 共 21 用例。

**仍可改进**：在 `buildEras` 的文档注释里显式写「不依赖调用方排序」，让调用者不必猜。

---

### R3 `client:media` 的 JS 边界与 CSS 断点是两处手写

**严重度**：低（改一处忘另一处就会出现空白区）

**证据** — 四处都是字面量 `1024`：

| 位置 | 用途 |
|---|---|
| [timeline.astro](src/pages/timeline.astro) | `client:media` + `@media` |
| [index.astro](src/pages/index.astro) | `client:media` + `@media` |

`src/design/tokens.ts` 有 `breakpoint.lg = 1024`，但 Astro 的 `client:media` 只接受字符串，无法引用变量——这是平台限制。

**风险**：将来改断点时若只改 CSS，会出现「容器可见但组件没挂载」的空白区。

**怎么修**：在 `docs/STYLE-GUIDE.md` 的断点章节列出「改断点需同步这里 4 处」。不建议为此引入构建期生成。
